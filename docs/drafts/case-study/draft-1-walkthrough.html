Walkthrough

01 · Sign in

Sign in with a WhatsApp code, not a password.

Most customers already live in WhatsApp, so the one-time code goes there and autofills. Location comes next, explained before the system asks, and there's no way to land on Home half set up.

02 · Pick clothes

A live estimate while you pick, the real count at pickup.

Tabs for Men, Women, Kids and Home, steppers on every row, and variants in a bottom sheet so the list keeps its place. The bar at the bottom updates as you tap.

03 · Review & book

Every rupee is computed on the server.

The app only sends item ids and quantities. A Cloud Function prices the order and applies the promo in the same transaction that counts the redemption, so nobody can replay CLOTHLAB50.

Decisions

Why it's built this way.

Commission is set per order, and the partner never sees it.

Why ▾

The admin can try different rates without renegotiating contracts or redeploying anything. The partner app only shows cash collected and what they keep, so a changing percentage never causes friction.

Taking cash is a confirmation, not a form.

Why ▾

The partner taps "Got ₹410 cash" instead of typing an amount. Fewer taps, fewer typos, and the amount always matches the order.

The delivery line shows FREE instead of disappearing.

Why ▾

Every order stores a delivery charge, currently zero. Charging later is a data change, not a redesign, and customers already read the line as a perk.
